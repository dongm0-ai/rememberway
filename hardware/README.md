# REMEMBER WAY 하드웨어 (목걸이 + 집 수신기)

하드웨어는 **생성형 AI가 아니라 입력 장치**예요. 생성형 AI는 앱(서버)에서만 씁니다.

| 장치 | 보드 | 하는 일 | 판단 방식 |
|---|---|---|---|
| **목걸이** `necklace/` | XIAO ESP32-C3 (시험은 SuperMini) + GPS NEO-6M + 부저 + 배터리 | ① 블루투스 이름표 `RW-NECKLACE` ② 휴대폰 버튼으로 부저 ③ GPS 30초마다 보드 안에 기록 | 없음 (기록만) |
| **집 수신기** `home_receiver/` | SuperMini ESP32-C3 (USB 전원) + 문 센서 | 문이 움직인 뒤 목걸이 신호가 정해진 시간 동안 없으면 텔레그램 알림 + 앱 링크 | **코드 규칙** |

**하지 않는 것:** 실시간 위치 추적은 하지 않아요 (통신 모듈이 없어요). GPS 기록은 보드 안에만 있고, USB로 앱에 옮길 때만 밖으로 나가요. 서버에 저장하지 않아요.

## 앱과 연결되는 곳

| 하드웨어 | 앱 화면 | 생성형 AI |
|---|---|---|
| 집 수신기 텔레그램 알림의 링크 `…/report?out=14:03` | 화면 1: 외출 시각과 지난 시간이 미리 채워짐 | 호출 ① 말 → 경찰용 정보 |
| 목걸이 GPS 기록 (`DUMP`) | `/gps`: 오래 머문 곳(코드) → 되묻기 질문(AI) → 보호자 확인 → 일지 | 호출 ⑦ 되묻기 질문·정리 문장 |
| 목걸이 블루투스 | `/find`: 근처에서 신호 잡기 + 소리 울리기 (안드로이드 크롬) | 없음 |

## 연결 (코드 핀 번호 = SuperMini 글자 = XIAO 글자)

| 부품 | 코드 핀 | SuperMini | XIAO |
|---|---|---|---|
| 부저 + (긴 다리 / S) | 3 | 3 | D1 |
| 문 센서 (집 수신기) | 4 | 4 | D2 |
| GPS TX | 20 | 20 | D7 |
| GPS RX | 21 | 21 | D6 |
| GPS VCC / 부저 −, 문 센서 다른 선, GPS GND | 3V3 / GND | 3V3 / GND | 3V3 / GND |

SuperMini는 2·8·9번을 쓰지 않아요 (켜질 때 쓰는 핀). 파란 불은 8번 (LOW일 때 켜짐).

## 아두이노 설정 (두 장치 공통)

1. 보드: `ESP32C3 Dev Module` (XIAO는 `XIAO_ESP32C3`)
2. 툴 → USB CDC On Boot → **Enabled**
3. 툴 → Partition Scheme → **Huge APP (3MB No OTA/1MB SPIFFS)** ← 블루투스·와이파이라 코드가 커서 꼭 바꿔야 해요
4. 목걸이만: 라이브러리 매니저에서 **TinyGPSPlus** (Mikal Hart) 설치. 집 수신기는 추가 라이브러리가 없어요.

## 집 수신기 준비: 텔레그램 봇

1. 텔레그램에서 **@BotFather** → `/newbot` → 봇 이름 정하기 → **토큰**을 받아요 (남에게 보여 주지 마세요).
2. 만든 봇에게 아무 말이나 한 번 보내요.
3. 브라우저에서 `https://api.telegram.org/bot토큰/getUpdates` 를 열면 `"chat":{"id":123456789` 가 보여요. 이 숫자가 **chat id**예요.
4. `home_receiver/secrets.example.h` 를 복사해 **`secrets.h`** 로 이름을 바꾸고, 와이파이 이름·비밀번호·토큰·chat id를 채워요.
   - `secrets.h` 는 GitHub에 올라가지 않아요 (`.gitignore`). 토큰이 새면 BotFather에서 `/revoke`.
   - ESP32-C3는 **2.4GHz 와이파이만** 돼요. 학교 와이파이가 막히면 **휴대폰 핫스팟**을 쓰세요.
5. 업로드 후 시리얼 모니터(115200)에 `TEST` → 텔레그램에 시험 메시지가 오면 성공이에요.

## 시연 모드

`home_receiver.ino` 의 `#define DEMO_MODE 1` → 20초 (실제는 `0` = 3분).
시연 순서: 목걸이 켜기 → 수신기 화면에 "집에 있음" → 문 센서 자석 떼었다 붙이기 → 목걸이를 들고 멀리 가거나 금속 통에 넣기 → 20초 뒤 텔레그램 알림 → 링크 눌러 앱 화면 1 → 목걸이를 다시 가까이 → "돌아오신 것 같아요".

## 목걸이 기록 앱으로 옮기기

- 노트북 크롬에서 앱 `/gps` → **목걸이에서 바로 가져오기** → 포트 선택 (아두이노 시리얼 모니터는 닫아 두기)
- 또는 시리얼 모니터에 `DUMP` → BEGIN~END 사이를 복사 → `/gps` 의 "기록 글을 붙여 넣기"
- 목걸이 GPS가 아직이면 휴대폰 GPS 기록 앱(CSV·GPX 내보내기)으로 모은 파일도 같은 화면에서 읽어요. 발표 때는 "휴대폰으로 모은 사전 기록"이라고 밝혀요.

## 알려진 한계 (발표에서 그대로 말하기)

- 블루투스 거리는 보통 10~30m, 벽·사람에 따라 달라요. "신호 없음 = 외출"은 추정이라 보호자가 확인해야 해요.
- 문이 움직인 뒤 다른 가족이 나간 경우, 목걸이가 집에 있으면 알림이 가지 않아요. 목걸이를 두고 나가시면 알림이 가지 않아요 (Doyle 등 2024: 목에 거는 방식도 불편해서 바꾸는 사람이 있었음).
- GPS는 실내에서 위치를 거의 못 잡아요. 처음 켜면 밖에서 5~15분 걸려요.
- 텔레그램 전송은 시연용으로 인증서 확인을 생략했어요 (`setInsecure`).
