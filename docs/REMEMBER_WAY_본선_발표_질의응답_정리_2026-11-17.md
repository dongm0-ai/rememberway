# REMEMBER WAY AI — 본선 발표·질의응답 정리 (2026-11-17)

> 가는 길에 읽는 용도예요. 굵은 글씨만 읽어도 발표할 수 있게 정리했어요.

---

## 1. 한 문장 (외우기)

**"어르신이 GPS를 끄거나 목걸이·휴대폰을 두고 나가셨을 때, 보호자가 등록한 추억의 장소와 최근 30일 GPS 기록에서 자주 머문 곳을 바탕으로 확인할 곳을 정리해 찾기를 돕는 보호자용 프로그램이에요."**

---

## 2. 예선 이후 달라진 것 (11/15~17)

| 예선 때 | 지금 (본선) |
|---|---|
| 기기 없이 보호자 **기억만** 사용 | **목걸이 GPS 기록 + 보호자 기억**을 같이 사용 |
| 실시간 위치 없음 | 목걸이 → 어르신 휴대폰 앱 → 서버 → 보호자 화면으로 **실시간 위치** |
| 자주 가는 곳 = 보호자가 일지에 적은 곳 | **GPS로 자주 머문 곳을 코드가 찾고, AI가 보호자에게 되묻기** |
| 하드웨어 없음 | **목걸이**(GPS·블루투스·부저) + **현관 수신기**(문 센서) |

## 3. 전체 흐름 (그림처럼 기억하기)

```
[평소]
목걸이 GPS ──블루투스──▶ 어르신 휴대폰 앱 ──인터넷──▶ 서버(30일만 보관)
                                                     │
               코드: 최근 30일에서 "자주 머문 곳" 찾기 ◀┘
                      │
               AI: "석교동 어딘가에 13일 머무셨는데 어떤 곳인가요? 좋아하시는 곳인가요?"
                      │
               보호자: ❤ 추억의 장소 / 📍 그냥 자주 가는 곳 / ✕ 빼기

[실종]
현관 수신기: 문 열릴 때 목걸이 감지 → 텔레그램 알림 → 앱 열림
보호자가 말하기 → AI가 경찰용 정보로 정리 + 빠진 것 되묻기
코드가 확인할 곳 순서 정하기 (추억의 장소·자주 머문 곳·목걸이 마지막 위치)
근처에 가면 → 휴대폰으로 목걸이 소리 울려서 찾기
```

## 4. 생성형 AI가 하는 일 vs 코드가 하는 일 (질문 많이 나옴!)

| 생성형 AI (Upstage Solar → Gemini) | 코드 (규칙) |
|---|---|
| 보호자 말 → 경찰이 쓸 정보로 정리 | 확인할 곳 **순서·점수** |
| 빠진 정보 **되묻기** | GPS에서 **머문 곳 계산** |
| GPS로 찾은 곳이 **어떤 곳인지 보호자에게 되묻는 질문** 만들기 | 30일 지난 기록 **자동 삭제** |
| 일지 문장 정리 | AI가 만든 답 **검사** (원문에 없는 말·숫자 걸러냄) |

**왜 나눴나요?** → AI는 말을 잘 다루지만 틀릴 수 있어요. 그래서 **판단(순서·계산)은 코드**가 하고, **AI는 말을 다루는 일**만 해요. AI 답은 코드가 한 번 더 검사해요.

**AI를 빼면?** → 보호자가 정해진 칸에 직접 다 채워야 하고, GPS로 찾은 곳이 어디인지 물어봐 주는 사람이 없어요.

## 5. 숫자와 근거 (질문 나오면 표 보고 답하기)

| 숫자 | 뜻 | 근거 |
|---|---|---|
| **30일** | GPS 기록을 보는 기간, 서버 보관 기간 | Bayat 외 2020 (노인 GPS를 4주 동안 모음) |
| **10초** | 목걸이가 움직일 때 위치 보내는 간격 | Shoval 외 2008 (치매 어르신 GPS 연구) |
| **3분** | 3분 넘게 안 움직이면 위치 보내기 쉼 | Bayat 외 2020 (3분 넘게 머물면 "정지") |
| **머문 곳 계산** | 그날 속력이 느리고 방향이 제멋대로면 머문 것, GPS가 오래 끊기면 건물 안에 머문 것 | 박진관·오수열 2016, 스마트미디어저널 (식 그대로) |
| **5%** | "유난히 크다"를 판단하는 기준 | 같은 논문 (유의수준 5%) |
| **4번 · 94m** | 4번 넘게, 94m 안에서 머문 곳을 한 장소로 묶음 | Bayat 외 2020 (노인 5명에게 정한 값 32~97m의 가운데) |
| 우선순위 점수 (추억 +3 등) | 확인할 곳 순서 | **학생 초안 (임의 설정, 실험으로 조정)** — 예선과 같음 |

**외울 말:** "숫자는 저희가 정하지 않고 **논문에 나온 값**을 썼습니다. 근거가 없는 것은 숫자를 정하지 않고 **현장에서 직접 재서** 정했습니다."
(예: 목걸이가 흔들리는 정도, 현관 문턱에서 블루투스 세기 → `CAL` 명령으로 직접 잼)

## 6. 시험 결과 (솔직하게 말하기)

**가짜 30일 기록**으로 시험했어요 (어르신 데이터를 함부로 모을 수 없어서).

| 장소 | 실제로 간 날 | 프로그램이 찾은 날 |
|---|---|---|
| 경로당 (건물 안) | 13일 | **13일** ✅ |
| 공원 (밖에서 서성임) | 6일 | **3~5일** ⚠️ |
| 시장 (가끔) | 3일 | **0~2일** (4번 미만이라 빠짐) |

**말할 문장:** "건물 안에 머문 곳은 GPS가 끊기니까 잘 찾았고, 밖에서 천천히 서성인 곳은 걷는 것과 헷갈려서 일부 놓쳤습니다. 그래서 **AI가 보호자에게 되묻고, 보호자가 직접 추억의 장소를 등록**해서 보완합니다."

## 7. 예상 질문과 답

**Q1. 그냥 GPS 위치 추적기랑 뭐가 달라요?**
→ 위치 추적기는 **켜져 있고 가지고 있을 때만** 쓸모 있어요. 저희는 **GPS를 끄거나 두고 나가셨을 때**를 위해, 평소 기록에서 **자주 머문 곳과 추억의 장소**를 정리해 어디부터 찾을지 알려 줘요.

**Q2. 생성형 AI는 어디에 써요?**
→ ① 보호자가 당황해서 말한 내용을 **경찰이 쓸 정보로 정리**, ② **빠진 것 되묻기**, ③ GPS로 찾은 장소가 **어떤 곳인지 보호자에게 묻는 질문** 만들기. 계산과 순서는 코드가 해요.

**Q3. AI가 틀리면요?**
→ AI 답은 코드가 검사해요. 보호자 말에 **없는 내용**은 ⚠ 표시하고, 질문에 **입력에 없는 숫자**나 "예측·확률" 같은 말이 있으면 버리고 기본 질문을 써요. AI가 고장 나면 **정해진 칸에 직접 입력하는 방식**으로 바뀌어요.

**Q4. 어르신 위치를 서버에 저장하면 개인정보는요?**
→ 이름·주소는 저장하지 않고 **좌표와 시각만** 저장해요. **30일이 지나면 자동으로 지워져요** (개인정보 보호법: 기간이 지나면 바로 파기). 찾은 뒤에는 [기록 모두 지우기]로 바로 지울 수 있어요. AI에는 좌표 없이 **"석교동 어딘가"처럼 동 이름만** 보내요.

**Q5. 위치 정보를 모아도 되나요? (법)**
→ 위치정보법 **제15조**에 따라 **본인 동의**가 필요해요. 시제품은 **팀원 본인 데이터로만** 시험했어요. 실제 서비스를 하려면 신고(제9조)도 필요하다는 걸 확인했어요.

**Q6. 어르신이 휴대폰을 안 들고 나가시면요?**
→ 그러면 실시간 위치는 안 와요. 그래서 **평소 기록으로 정리한 자주 머문 곳과 추억의 장소**가 필요한 거예요. 다음 단계로는 **유심이 들어간 GPS**를 만들어서 휴대폰 없이도 위치를 보내게 할 계획이에요.

**Q7. 왜 목걸이예요?**
→ 연구에서 GPS 기기를 **목줄·열쇠고리 방식으로 가장 많이 썼어요** (Doyle 외 2024, 91%). 건강보험공단 **배회감지기**도 몸에 차는 방식이에요. 다만 목에 거는 게 불편해서 바꾼 사람도 있어서, 착용 시험이 더 필요해요.

**Q8. "자주 간 곳"이면 다 좋아하는 곳이에요?**
→ 아니에요. **병원·약국처럼 자주 가도 좋아하지 않는 곳**이 있고, **고향처럼 추억이 있어도 요즘 안 가는 곳**도 있어요 (Koester 2006: 예전 집이나 좋아하던 곳으로 가려 함). 그래서 AI가 **보호자에게 물어보고**, 보호자가 직접 추억의 장소를 등록해요.

**Q9. 30일은 왜 30일이에요?**
→ 노인 GPS 연구(Bayat 2020)에서 **4주** 동안 기록을 모았고, 저희 일지 규칙("30일에 4번 넘으면 자주")과도 맞아요. 60일은 근거를 못 찾아서 안 썼어요.

**Q10. 머문 곳은 어떻게 계산해요? (쉽게)**
→ ① 그날 속력을 보고 **가장 느린 무리**를 "멈춤"으로 봐요. ② 멈춘 사람은 GPS 방향이 **제멋대로 흔들려요** → 흔들림이 크면 머문 곳이에요. ③ 건물에 들어가면 GPS가 **끊기는데**, 오래 끊겼는데 거의 안 움직였으면 건물 안에 머문 거예요. (박진관·오수열 2016)

**Q11. 실제 어르신으로 시험했어요?**
→ 아니요. 어르신 위치는 민감한 정보라 **가짜 기록과 팀원 데이터**로 시험했어요. 실제 사용자 시험은 다음 단계예요.

**Q12. 현관 수신기는 어떻게 외출을 알아요?**
→ 문이 열려 있는 동안 **문 앞에서 목걸이 신호가 잡히면** 알림을 보내요. 건강보험공단 **매트형 배회감지기**(현관 앞에서 감지하면 바로 알람)와 같은 원리예요. 문 앞 신호 세기 기준은 **현장에서 직접 재서** 정해요.

**Q13. 블루투스는 몇 m까지 돼요?**
→ 장소마다 달라서 숫자로 정하지 않았어요 (Bluetooth SIG: 1m 미만~1km 넘게까지 다름). **저희가 시연 장소에서 직접 잰 값**으로 말할게요. ← (재고 나서 숫자 채우기: ___m)

## 8. 시연 순서 (2분)

1. 첫 화면 → **📍 목걸이 위치 보기**: 지도에 목걸이 위치
2. **현관 수신기**: 문 센서 자석 떼기 → 목걸이 든 사람이 지나감 → **텔레그램 알림** → 링크 누르면 앱이 열리고 외출 시각이 채워져 있음
3. **실종 정리 화면**: 보호자처럼 말하기 → AI가 정리·되묻기 → **목걸이 마지막 위치 [단서에 넣기]**
4. **확인할 곳 지도**: 추억의 장소·자주 머문 곳 순서
5. **🔔 목걸이 찾기**: 휴대폰 버튼 → 목걸이에서 삐삐
6. (시간 있으면) **🛰️ GPS로 자주 머문 곳**: AI 되묻기 질문 보여 주기

## 9. 한계 (먼저 말하면 점수에 좋아요)

- 밖에서 서성인 곳은 **일부 놓쳐요** → 보호자 되묻기·직접 등록으로 보완
- 어르신이 **휴대폰을 두고 나가시면** 실시간 위치가 안 와요 → 다음 단계: 유심 GPS
- **목걸이를 두고 나가시면** 아무것도 못 해요 (연구에서도 따로 재는 알려진 문제)
- 실제 어르신 대상 시험은 아직 못 했어요 (가짜 기록·팀원 데이터)
- 확인할 곳 **점수는 학생 초안**이라 실험으로 조정해야 해요
