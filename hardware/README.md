# REMEMBER WAY 하드웨어 (목걸이 + 현관 수신기)

하드웨어는 **생성형 AI가 아니라 입력 장치**예요. 생성형 AI는 앱(서버)에서만 씁니다.
모든 숫자는 근거가 있거나, 근거가 없으면 **숫자를 정하지 않고 우리가 직접 재서(CAL)** 정합니다.

| 장치 | 보드 | 하는 일 | 근거 |
|---|---|---|---|
| **목걸이** `necklace/` | XIAO ESP32-C3 (시험은 SuperMini) + GPS NEO-6M + MPU-6050 + 부저 + 배터리 | ① 블루투스 이름표 `RW-NECKLACE` ② 휴대폰 버튼으로 부저 ③ **움직일 때만** GPS 10초마다 보드 안에 기록, 3분 넘게 멈추면 기록 쉼 | 공단 배회감지기 태그형(블루투스)·GPS형 / Shoval 외 2008(10초) / Bayat 외 2020(3분 정지, 멈추면 대기) |
| **현관 수신기** `home_receiver/` | SuperMini ESP32-C3 (USB 전원) + 문 센서 | 현관문이 열려 있는 동안 목걸이 신호를 듣고, 문턱 세기 이상이면 텔레그램 알림 + 앱 링크 | 공단 배회감지기 매트형(현관문 앞, 감지 즉시 알람) / Rafferty 외 2018 Safe Beacon(문 쪽 수신기, 신호 기준은 현장에서 잼) |

**하지 않는 것:** 실시간 위치 추적은 하지 않아요 (통신 모듈이 없어요). GPS 기록은 보드 안에만 있고, USB로 앱에 옮길 때만 밖으로 나가요. 서버에 저장하지 않아요.

## 연결 (코드 핀 번호 = SuperMini 글자 = XIAO 글자)

| 부품 | 코드 핀 | XIAO |
|---|---|---|
| 부저 + (긴 다리 / S) | 3 | D1 |
| 문 센서 (현관 수신기) | 4 | D2 |
| MPU-6050 SDA | 6 | D4 |
| MPU-6050 SCL | 7 | D5 |
| GPS TX | 20 | D7 |
| GPS RX | 21 | D6 |
| GPS·MPU VCC | 3V3 | 3V3 |
| 부저 −, 문 센서 다른 선, GPS·MPU GND | GND | GND |

SuperMini는 2·8·9번을 쓰지 않아요 (켜질 때 쓰는 핀). 파란 불은 8번 (LOW일 때 켜짐).

## 아두이노 설정 (두 장치 공통)

1. 보드: `ESP32C3 Dev Module` (XIAO는 `XIAO_ESP32C3`)
2. 툴 → USB CDC On Boot → **Enabled**
3. 툴 → Partition Scheme → **Huge APP (3MB No OTA/1MB SPIFFS)**
4. 목걸이만: 라이브러리 매니저에서 **TinyGPSPlus** (Mikal Hart) 설치. MPU-6050과 현관 수신기는 추가 라이브러리가 없어요.

## 우리가 직접 재서 정하는 것 (CAL)

| 무엇 | 어떻게 | 왜 숫자를 안 정했나 |
|---|---|---|
| 목걸이 "움직임" 기준 | 목걸이를 차고 10초 가만히 앉아 시리얼에 `CAL` → 가만히 있을 때 가장 큰 흔들림보다 크면 움직임 | 움직임 민감도에 대한 근거 자료가 없음 |
| 현관 "문턱" 신호 세기 | 목걸이를 차고 문턱에 10초 서서 현관 수신기에 `CAL` → 그때 가장 약한 신호 이상이면 문 앞 | 블루투스 세기는 장소마다 달라 거리로 바꿀 수 없음 (Bluetooth SIG, NIST 2022). Safe Beacon도 현장에서 잼 |

## 현관 수신기 준비: 텔레그램 봇

1. 텔레그램에서 **@BotFather** → `/newbot` → 봇 이름 정하기 → **토큰**을 받아요 (남에게 보여 주지 마세요).
2. 만든 봇에게 아무 말이나 한 번 보내요.
3. 브라우저에서 `https://api.telegram.org/bot토큰/getUpdates` 를 열면 `"chat":{"id":123456789` 가 보여요. 이 숫자가 **chat id**예요.
4. `home_receiver/secrets.example.h` 를 복사해 **`secrets.h`** 로 이름을 바꾸고 채워요. `secrets.h` 는 GitHub에 올라가지 않아요. 토큰이 새면 BotFather에서 `/revoke`.
   ESP32-C3는 **2.4GHz 와이파이만** 돼요. 학교 와이파이가 막히면 **휴대폰 핫스팟**.
5. 업로드 후 시리얼 모니터(115200)에 `TEST` → 텔레그램에 시험 메시지가 오면 성공.

## 시연 순서

목걸이 켜기(삐 두 번) → 문 센서 자석 떼기(문 열림) → 목걸이를 찬 사람이 문턱을 지나감 → 자석 붙이기(문 닫힘) → 텔레그램 알림 → 링크 눌러 앱 화면 1(외출 시각 채워짐) → 앱 `/find` 에서 목걸이 연결 → 소리 울리기.

## 목걸이 기록 앱으로 옮기기

- 노트북 크롬에서 앱 `/gps` → **목걸이에서 바로 가져오기** → 포트 선택 (아두이노 시리얼 모니터는 닫아 두기)
- 또는 시리얼 모니터에 `DUMP` → BEGIN~END 사이를 복사 → `/gps` 의 "기록 글을 붙여 넣기"

## 알려진 한계 (발표에서 그대로 말하기)

- **GPS 전원은 아직 끄지 못해요.** 3분 멈추면 *기록*만 쉬고 GPS 모듈은 켜져 있어요. u-blox 공식 자료상 NEO-6을 잠재운 뒤 깨우려면 EXTINT 핀이나 정해진 시간이 필요한데, 우리 GPS 보드(GY-GPS6MV2)에는 EXTINT 핀이 밖으로 나와 있지 않아요. → 배터리를 아끼는 건 다음 단계(전원 스위치 부품 추가 등)로 남김.
- 문이 열릴 때 어르신이 현관 근처에 **계시기만 해도** 알림이 갈 수 있어요 (매트형도 밟으면 울림). 목걸이를 두고 나가시면 알림이 가지 않아요 (Shoval 2008이 "장치 없이 나간 경우"를 따로 잴 만큼 알려진 문제).
- GPS는 실내에서 위치를 거의 못 잡아요. 처음 켜면 밖에서 위치를 잡기까지 시간이 걸려요 (u-blox 자료: 처음부터 찾을 때 약 27초).
- 텔레그램 전송은 시연용으로 인증서 확인을 생략했어요 (`setInsecure`).
- 배터리 시간·블루투스 거리는 우리가 잰 값만 발표에 씁니다.
