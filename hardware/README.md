# REMEMBER WAY 하드웨어 (목걸이)

하드웨어는 **생성형 AI가 아니라 입력 장치**예요. 생성형 AI는 앱(서버)에서만 씁니다.

| 장치 | 보드 | 하는 일 |
|---|---|---|
| **목걸이** | ESP32-C3 SuperMini + GPS NEO-6M + 수동 부저 + 배터리 | ① GPS 위치를 블루투스로 어르신 휴대폰 앱에 전달 ② 앱이 보낸 글자(`BUZZER_FIND` 등)로 부저 울림 |

현관 수신기는 2026-11-20에 뺐어요 (`home_receiver/` 삭제).

**이 저장소에는 목걸이 펌웨어 소스(.ino)를 두지 않아요.** 옛 펌웨어(`necklace/necklace.ino` — 이름 `RW-NECKLACE`, 서비스 `7a1e0001-…`)는
지금의 앱·웹과 맞지 않아 2026-11-20에 지웠어요. 서버·웹·앱은 펌웨어 소스 없이 돌아가고, 목걸이는 아래 "블루투스 약속"만 지키면 돼요.

## 실시간 위치와 원격 부저

```
위치:  목걸이 →(블루투스)→ 어르신 휴대폰 앱 android/ →  서버 /api/loc  → 보호자 웹앱 /track 지도
부저:  보호자 웹앱 /find [소리 울리기] → 서버 /api/loc → 어르신 휴대폰 앱 →(블루투스)→ 목걸이 부저
```

- 목걸이에는 통신 모듈이 없어서 **어르신 휴대폰이 반드시 사이에 있어야** 해요. 어르신이 휴대폰을 갖고 계시고, 목걸이와 가깝고, 앱이 켜져 있고, 휴대폰이 인터넷에 연결돼 있을 때만 위치가 오고 부저가 울려요.
- 부저 요청은 60초 안에 전달되지 않으면 버려요 (한참 뒤에 갑자기 울리지 않게).
- 앱 받기: GitHub 저장소 → Releases → `tracker-apk` → `RememberWay-location.apk` (시제품, 디버그 빌드).

## 등록 순서

1. 보호자 웹앱에서 어르신을 등록하면 **연결 코드 16글자**가 나와요 (설정 → 어르신 폰 연결 코드).
2. 어르신 휴대폰 앱에 그 코드를 넣어요.
3. 앱에서 [목걸이 찾기]를 눌러 주변 목걸이 중 하나를 골라요. 앱이 그 목걸이를 기억하고 서버에 알려요.
4. 보호자 웹앱 설정·`/find` 화면에 "등록된 위치 단말"로 보여요.

목걸이를 바꾸면 앱에서 다시 고르기만 하면 돼요. 서버에는 목걸이 이름과 펌웨어가 붙인 id만 남고, 블루투스 주소는 보내지 않아요.

## 블루투스 약속 (펌웨어 ↔ 앱 `android/` ↔ 웹 `/find` 가 같은 값을 써야 함)

| 항목 | 값 |
|---|---|
| 이름 | `GPS-TRACKER-` 로 시작 (예: `GPS-TRACKER-001`) |
| 서비스 | `a73e0001-1e4d-4a5b-9c3d-120000000001` — **광고에 넣어야** 앱이 찾아요 |
| 위치 | `a73e0002-…` READ · NOTIFY |
| 부저 | `a73e0003-…` READ · WRITE · NOTIFY |

**위치**
1. 좌표가 유효하면 위치 특성의 저장 값을 전체 JSON(8개 칸: `device_id`, `latitude`, `longitude`, `fix_age_ms`, `speed_kmh`, `gps_time`, `sequence`, `firmware_version`)으로 둬요.
2. 알림(Notify)은 `GPS:<순번>` 처럼 20바이트 이하만 보내요. 앱이 알림을 받으면 위치 특성을 READ 해서 전체 JSON을 가져가요.
3. 좌표가 없으면 저장 값 `{"status":"waiting"}`, 알림 `GPS:WAITING`. 앱은 이때 서버에 아무것도 보내지 않아요.
4. 서버는 `fix_age_ms` 가 0~3000 인 위치만 받아요. 오래된 좌표는 보내지 마세요.

**부저**

| 앱 → 목걸이 (WRITE, 글자) | 목걸이 → 앱 (NOTIFY, 값으로도 저장) |
|---|---|
| `BUZZER_FIND` | `ACK_FIND` — 20초 뒤 저절로 멈춤 |
| `BUZZER_ON` | `ACK_ON` — 10초 뒤 저절로 멈춤 |
| `BUZZER_OFF` | `ACK_OFF` |
| 그 밖 | `ERR_COMMAND` (PWM 실패는 `ERR_PWM`) |

앱은 쓴 뒤 3초 안에 알림이 없으면 부저 특성을 한 번 READ 해서 확인해요. 그래서 대답 글자를 알림으로 보내면서 **특성 값으로도 저장**해 둬야 해요.
앱이 서버에 "목걸이가 받았어요"라고 알리는 것은 이 ACK를 받았을 때뿐이에요. 실제로 소리가 났는지는 알 수 없어요.

## 연결 (핀)

| 부품 | ESP32-C3 핀 |
|---|---|
| GPS TX (→ ESP32가 받음, 9600bps) | 4 |
| 부저 제어 (1kΩ → NPN 트랜지스터 베이스, 베이스-GND 10kΩ) | 5 |
| GPS VCC / GND | 5V(모듈 허용 전압 확인) / 공통 GND |

GPIO로 부저를 직접 구동하지 않아요 (트랜지스터 사용). SuperMini는 2·8·9번을 쓰지 않아요 (켜질 때 쓰는 핀).

## 아두이노 설정

1. 보드: `ESP32C3 Dev Module`
2. 툴 → USB CDC On Boot → **Enabled**
3. 툴 → Partition Scheme → **Huge APP (3MB No OTA/1MB SPIFFS)**
4. 라이브러리 매니저에서 **TinyGPSPlus** (Mikal Hart) 설치

## 알려진 한계 (발표에서 그대로 말하기)

- **부저 특성이 열려 있어요.** 지금 펌웨어는 블루투스 인증·암호화가 없어서 근처의 다른 휴대폰도 부저를 울릴 수 있어요. 실제로 쓰기 전에 막아야 해요.
- 어르신이 **휴대폰을 두고 나가시면** 위치도 원격 부저도 되지 않아요. 그때는 근처에서 `/find` 의 "직접 연결"만 쓸 수 있어요.
- GPS는 실내에서 위치를 거의 못 잡아요. 처음 켜면 밖에서 위치를 잡기까지 시간이 걸려요 (u-blox 자료: 처음부터 찾을 때 약 27초).
- GPS 전원은 끄지 못해요. 배터리를 아끼는 건 다음 단계로 남겼어요.
- 배터리 시간·블루투스 거리는 우리가 잰 값만 발표에 씁니다.
