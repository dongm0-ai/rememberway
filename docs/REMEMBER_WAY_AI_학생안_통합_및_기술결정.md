# REMEMBER WAY AI — 학생 정리안 통합 및 기술 결정

- 작성: 2026-10-25 · 팀: 그럴게요 (동명중, 김동욱·양준원)
- 입력: 학생들이 정리한 기획 메모(브레인스토밍 3 + 개발 프롬프트 2) ↔ 10/20 확정안
- 이 문서의 목적: 두 문서를 하나로 합치고, 기술 스택과 GPS 축적 여부를 결정한다.

## 1. 현재 상태 진단

학생 정리안은 **10/18 해커톤 초안의 구조**(사전 등록 추억 장소 → 반경 → 확률 순 Top 3)에 머물러 있다. 10/20 확정안(위치 예측 폐기, 당일 대화, 사후 기록)이 학생에게 전달되지 않았거나 설득되지 않은 상태. 구현 전에 반드시 맞춘다.

맞추는 방법: 학생 정리안 7절 "아직 해결 안 된 고민" 두 개("예상 장소에 없으면?", "반경 계산이 유효한가?")가 Top 3 방식의 한계 그 자체다. 이 고민에서 출발해 "그래서 예측 대신 정리·되묻기로 간다"를 학생이 스스로 결론 내게 한다. 탐구기록물에는 학생의 결론으로 기록한다.

## 2. 학생 정리안에서 반영 / 수정 / 보류

### 수정

| 항목 | 문제 | 수정 |
|---|---|---|
| 예상 장소 **확률 순 Top 3** | 확률에 근거 없음. AI 판단은 편향 위험(트리아지 LLM 연구). 포항 ZIP과 동일 구조. 한국 GPS 분석: 10명 중 8명 목적지 미도착 → 추억 장소 Top 3는 발견 위치와 어긋나기 쉬움 | 순위·확률 없이 **오늘 목적지·경로·교차로·추억 장소**를 거리와 보호자 근거와 함께 표시. 판단은 경찰·보호자 |
| 사전 등록 **필수** | 사전등록률 30% 미만. 등록 안 한 사람은 못 씀 | **선택**. 등록 없어도 당일 대화로 같은 요약이 나옴. 있으면 칸이 미리 채워짐 |
| "1시간 이내 43% / 1일 이내 46% → 초기 1~2시간이 가장 중요" | 그 수치는 "빨리 찾는 경우가 많다"는 뜻이지 1~2시간 뒤 위험하다는 근거가 아님 | 위험 근거는 Koester: 24시간 내 발견 시 생존율 95%, 이후 38% |
| 근거 통계 15,836명(2024) | 맞지만 구버전 | 2025년 16,586건, 2026 1~7월 +14.4% (경찰청) |

## 3. GPS를 평소 들고 다니며 경로를 축적하는 것 — 판정: 핵심 아님

**반대 이유**
1. 어르신이 폰을 들고 나가야 한다. 안 들고 나간 날이 우리 전제이고, 들고 나갔으면 실시간 위치가 있으니 축적 데이터가 필요 없다.
2. 평소 동선은 "어디로 출발했나"를 알려 줄 뿐 "지금 어디 있나"를 알려 주지 않는다 (한국일보·한양대 GPS 분석, 행복GPS 분석: 되돌아옴 20.7%).
3. 24시간 위치 축적은 치매관리법 개정안(2026.1)의 최소 수집·동의 원칙과 부딪힌다. 7쪽 윤리 방어가 어려워진다.
4. 구현 비용: 브라우저 Geolocation은 앱이 열려 있는 동안만 동작. 백그라운드 축적은 네이티브 앱이나 별도 기기가 필요 → 2명·11월 초까지 불가.
5. 이미 있다: 배회감지기(행복GPS 38,721명), 스마트태그(지자체 보급), ZIP(동선 축적). 그 서비스들이 있어도 실종은 는다.

**조건부 가능한 형태 (예선 뒤)**
- "GPS 로그가 이미 있으면(배회감지기 앱 내보내기 등) 화면 0의 추억 장소·습관을 자동으로 채우는 **입력원**". 우리가 축적하지 않고, 있는 로그를 LLM이 "오후에 ○○동 방향을 자주 간다"로 문장화.
- 파이프라인 변경 없음. 발표에서 "기기 있는 사람도 쓸 수 있다"를 보여 줌. 실제 행복GPS 로그는 받을 수 없으니 **모의 로그**로만 시연하고 그렇게 명시.

**학생에게 설명할 말:** "GPS 축적은 좋은 생각이고, 그걸 하는 서비스가 이미 있다. 그 서비스들이 있어도 실종이 늘어난다. 우리는 그 서비스들이 못 하는 날을 맡는다. 로그가 있으면 읽어 주는 건 나중에 넣자."

## 4. 기술 스택 결정

| 항목 | 학생안 | 결정 |
|---|---|---|
| 프레임워크 | Next.js (App Router, TS, Tailwind) | **유지** |
| AI | Gemini API / Google AI Studio | **Claude API** (Anthropic SDK). JSON 스키마 출력·이미지 입력 지원 → 호출 ①~④ 전부 가능 |
| 배포 | Vercel | **GitHub(코드) + Vercel 또는 Cloudflare Workers(서버리스 함수)** |
| API 키 | 환경변수 | 서버 환경변수. **브라우저에 두지 않음** |

**GitHub Pages만으로는 안 되는 이유:** 정적 호스팅이라 키를 둘 곳이 없다. 브라우저에서 직접 Claude API를 부르면 키가 소스에 노출된다(F12로 보임). 서버리스 함수 하나(`/api/extract`)가 키를 들고 Claude를 부르고, 프론트는 그 경로만 호출한다.

**차선(시간이 없을 때):** GitHub Pages + 시연 시 키를 화면에서 입력받아 메모리에만 둠. 저장 금지. "제품"이 아니라 "시연"으로 명시.

**라우트 구조 (학생안 → 확정)**
```
app/api/extract/route.ts     # 호출 ① 발화·사진 → 단서 JSON (학생안 parse-places)
app/api/followup/route.ts    # 호출 ② 빈 항목 → 되묻기 질문 3개
app/api/describe/route.ts    # 호출 ③ 사진 → 인상착의 문장
app/api/record/route.ts      # 호출 ④ 사건 서술 → 요약·패턴·예방 계획 (예선 뒤)
components/
  SituationInput.tsx         # 화면 1
  ConfirmAndAsk.tsx          # 화면 2
  PoliceSummary.tsx          # 화면 3 (지도 + 행동 수칙 3)
  Register.tsx               # 화면 0 (예선 뒤)
  AfterFound.tsx             # 화면 4 (예선 뒤)
```

**시스템 프롬프트 공통 제약 (학생안 5절 반영)**
- 자료에 없는 정보는 추정하지 않는다 → 모르면 `null`
- 위험한 행동은 안내하지 않는다 → 행동 수칙은 코드가 고름, AI는 안 만듦
- 모르면 112·치매안심센터 연락 안내 → 화면 1 최상단 고정
