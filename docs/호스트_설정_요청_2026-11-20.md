# 호스트 설정 요청 — 원격 부저·위치 단말 등록 켜기 (2026-11-20)

**누가 보나요:** Supabase와 Vercel 계정을 가진 호스트. 협업자는 두 서비스에 들어갈 수 없어서, 아래 순서대로 한 번씩만 해 주시면 됩니다.
**왜 필요한가요:** 보호자가 웹 `/find` 에서 [소리 울리기]를 누르면 **멀리 있어도** 어르신 휴대폰 앱을 거쳐 목걸이에서 소리가 나는 기능과, 어르신 휴대폰 앱이 연동한 목걸이를 서버에 등록하는 기능이 들어갔습니다. 코드는 저장소에 있지만 **Supabase 표 2개는 호스트가 만들어야** 켜집니다. 안 만들면 `/find` 에서 "단말 상태를 불러오지 못했어요 · 서버에 문제가 있어요"가 나옵니다.
무엇이 어떻게 바뀌었는지는 `docs/원격부저_위치단말_2026-11-20.md` 에 있습니다.

- `<도메인>` = 서비스 주소 (예: `https://rememberway.vercel.app`).
- **새로 넣을 환경변수는 없습니다.** 지금 쓰시는 환경변수(AI 키, 네이버 키, `SUPABASE_*`, `APP_URL`, `ALLOWED_HOSTS`, `MOCK_AI`)는 모두 그대로 둡니다.
- **순서는 ① → ② 를 권합니다.** 거꾸로 해도 고장 나지는 않습니다 — ①을 하기 전에 코드가 먼저 배포돼도 목걸이 위치 받기(`/track`)는 그대로 되고, 부저와 단말 표시만 ①을 할 때까지 안 됩니다.
- **키를 메신저·메일로 보내지 마세요.** 협업자에게 돌려줄 것은 각 단계의 "됐어요 / 안 됐어요"와 증상 한 줄뿐입니다 (맨 아래 "돌려주실 것").

## ① Supabase에 새 표 2개 만들기 (SQL)

**할 일**
1. Supabase 대시보드 → 이 서비스의 프로젝트 → 왼쪽 **SQL Editor** → **New query**.
2. 저장소의 `docs/supabase.sql` 파일을 열어, **`원격 부저·위치 단말 등록 (2026-11-20, 다시 Run 해도 안전)`** 이라고 적힌 주석 줄부터 **파일 끝까지** 복사해 붙여넣고 **Run**.
   - 파일 **전체**를 붙여넣어도, 몇 번 다시 Run 해도 안전합니다. 표 만들기는 모두 `create ... if not exists` 라서 이미 있는 표와 그 안의 데이터는 건드리지 않습니다.
3. "Success"가 나오면 끝.

**잘 됐는지 보는 법** — 같은 SQL Editor에서 아래를 따로 Run 해 보세요.
```sql
-- (1) 새 표 2개가 보여야 합니다 (2행)
select table_name from information_schema.tables
where table_schema = 'public'
  and table_name in ('device_commands','device_status')
order by 1;

-- (2) 둘 다 rowsecurity = true 여야 합니다 (2행) — 브라우저용 공개 키로는 읽고 쓸 수 없다는 뜻
select tablename, rowsecurity from pg_tables
where schemaname = 'public'
  and tablename in ('device_commands','device_status')
order by 1;

-- (3) 색인 (1행)
select indexname from pg_indexes where indexname = 'device_commands_dev_time';
```

**안 될 때:** 빨간 오류가 나오면 그 문장을 그대로 협업자에게 알려 주세요. `gen_random_uuid` 가 없다는 오류라면 SQL Editor에서 `create extension if not exists pgcrypto;` 를 먼저 Run 한 뒤 다시 해 보세요 (보통은 이미 켜져 있습니다 — 2026-11-17에 만든 `elders` 표가 같은 함수를 씁니다).

**이 표에 들어가는 것** (호스트가 알고 계셔야 해서 적습니다)

| 표 | 들어가는 것 | 지워지는 때 |
|---|---|---|
| `device_commands` | 어르신 폰 연결 코드의 **해시**, 명령 종류(울리기·멈추기), 진행 상태, 목걸이의 대답 글자, 누른 가족의 계정 id, 시각 | 서버가 하루 뒤 자동 삭제 / 어르신 삭제 때 |
| `device_status` | 연결 코드의 **해시**, 목걸이 이름(예: `GPS-TRACKER-001`)·펌웨어 id·버전, 블루투스·GPS 상태, 앱 버전, 시각 | 어르신 삭제 때 |

이름·주소·위치 좌표·블루투스 주소·연결 코드 자체는 넣지 않습니다.
`CLAUDE.md` 의 "서버 DB를 만들지 않는다" 규칙에 이 두 표를 **예외로 추가하는 지도교사 결정**이 필요합니다 (예외 1 푸시 구독, 예외 2 위치 기록에 이어). 결정되면 결정표와 `CLAUDE.md` 에 날짜와 함께 적어 주세요.

## ② 새 코드 배포 확인 (Vercel)

협업자가 올린 변경이 GitHub `main` 에 합쳐지면 Vercel이 자동으로 배포합니다. 환경변수를 바꾼 것이 없으므로 **따로 Redeploy 할 필요는 없습니다.**

**할 일**
1. Vercel → 프로젝트 → **Deployments** → 가장 위의 **Production** 배포가 `main` 의 최신 커밋이고 상태가 **Ready** 인지 봅니다.
   - 자동으로 배포되지 않았으면 그 배포 오른쪽 **⋯ → Redeploy**.
2. Vercel 무료 플랜의 **함수 12개 한도**는 그대로입니다 (새 API 파일을 만들지 않고 기존 `api/loc.js` 에 넣었습니다). 배포가 "함수 개수 초과"로 실패하면 협업자에게 알려 주세요.

**잘 됐는지 보는 법**
- 브라우저에서 `https://<도메인>/sw.js` → 맨 위쪽에 **`rw-v68`** (또는 그보다 큰 번호)이 보이면 새 화면 파일이 배포된 것입니다.
- 서버가 새 표를 읽을 수 있는지: PC의 PowerShell에서 아래 한 줄을 실행합니다. 아무것도 저장하지 않는 조회이고, `AAAA…` 는 아무 어르신에게도 연결되지 않은 시험용 글자입니다.
  ```powershell
  Invoke-RestMethod -Method Post -ContentType "application/json" -Uri "https://<도메인>/api/loc" -Body '{"action":"cmd.pending","key":"AAAAAAAAAAAAAAAA"}'
  ```
  | 나온 결과 | 뜻 |
  |---|---|
  | `ok : True`, `commands : {}` | ①·② 모두 성공 |
  | 오류 **503** (`STORE_ERROR`) | 코드는 배포됐지만 ①의 표가 아직 없음 → ①을 해 주세요 |
  | 오류 **400** (`BAD_ACTION`) | 아직 옛 코드가 배포돼 있음 → `main` 에 합쳐졌는지, 배포가 Ready 인지 확인 |

**안 될 때:** 배포가 실패(Error)로 끝나면 Vercel 배포 화면의 빨간 로그 마지막 몇 줄을 협업자에게 알려 주세요.

**되돌려야 할 때:** Vercel → **Deployments** → 바로 이전 Production 배포의 **⋯ → Promote to Production**(또는 Instant Rollback). ①에서 만든 표는 그대로 두어도 아무 영향이 없습니다 (옛 코드는 그 표를 쓰지 않습니다).

## ③ 어르신 폰 앱 새 판 확인 (GitHub 릴리스 `tracker-apk`)

어르신 폰용 앱이 새로 바뀌었습니다 (연결 코드 입력 → **목걸이 찾기·고르기** → 시작). `android/` 폴더 변경이 GitHub에 올라가면 Actions가 APK를 새로 만들어 같은 릴리스를 바꿉니다. **옛 APK는 지금 목걸이를 찾지 못하니**, 어르신 폰에는 새 APK를 깔아야 합니다.

**할 일**
1. GitHub 저장소 → **Actions** → **android-apk** 의 가장 최근 실행이 초록색(성공)인지 봅니다.
2. 저장소 → **Releases** → **tracker-apk** 의 설명에 적힌 "커밋 xxxxxxx"가 `android` 폴더의 마지막 커밋 앞 7글자와 같은지 봅니다.
3. (폰 설치는 협업자가 해도 됩니다) 어르신 폰에서 `RememberWay-location.apk` 를 받아 설치 → 앱에서
   ① 보호자 앱 **⚙ 설정 → 어르신 폰 연결 코드** 16글자를 넣고 → ② **[목걸이 찾기]** 를 눌러 목록에서 목걸이를 고르고 → ③ **[시작]**. 블루투스("근처 기기")·알림 권한을 허용합니다.

**안 될 때:** Actions 실행이 빨간색이면 그 실행 화면의 마지막 오류 줄을 협업자에게 알려 주세요.

## ④ 전체 확인 (호스트나 협업자 중 목걸이와 어르신 폰을 가진 사람이)

**시험용 어르신으로만 해 주세요.** 목걸이를 켜고, 어르신 폰 앱이 "목걸이 연결됨"인 상태에서 합니다.

1. 보호자 폰(또는 PC)에서 로그인 → 시험용 어르신 선택 → **⚙ 설정 → 어르신 폰 연결 코드** 아래에 **"등록된 위치 단말: GPS-TRACKER-… "** 가 보입니다.
2. **📍 실시간 위치 → 목걸이 소리로 찾기**(`/find`) → "위치 단말" 칸에 **"… · 휴대폰과 연결됨"** 이 보입니다.
3. **[소리 울리기 (20초)]** → "보내는 중…" → "휴대폰이 받았어요" → **"목걸이가 받았어요"** 로 바뀌고 목걸이에서 소리가 납니다. 누른 뒤 소리가 나기까지 **10초쯤** 걸릴 수 있습니다.
4. **[소리 멈추기]** → "소리를 멈췄어요".

**안 될 때(증상 한 줄씩)**
- "단말 상태를 불러오지 못했어요 · 서버에 문제가 있어요" → ①(표 만들기)이 안 된 것입니다.
- "아직 연동된 위치 단말이 없어요" → 어르신 폰 앱에 코드를 넣고 목걸이를 고른 뒤 [시작]을 눌렀는지 확인 (③).
- "보내지 못했어요 · 어르신 폰 연결 코드가 아직 없어요" → 보호자 앱 ⚙ 설정에서 연결 코드를 만들어 어르신 폰 앱에 넣습니다.
- "어르신 휴대폰에 닿지 못했어요" (60초 뒤) → 어르신 폰이 꺼졌거나, 인터넷이 끊겼거나, 앱이 멈춰 있습니다. 어르신 폰에서 앱을 열어 [시작]을 다시 누릅니다.
- "목걸이에 전달하지 못했어요" → 어르신 폰과 목걸이가 멀거나 목걸이가 꺼져 있습니다.
- "목걸이가 받았어요"인데 소리가 안 남 → 서버·앱은 정상입니다. 목걸이 부저 배선이나 전원을 봐야 합니다 (화면은 목걸이가 요청을 받았다는 것까지만 압니다).

## 알아 두실 것

- **Vercel 호출량이 늘어납니다.** 어르신 폰 앱이 켜져 있는 동안, 위치를 보내지 않을 때는 **10초에 한 번** 서버에 기다리는 부저 명령이 있는지 물어봅니다 (휴대폰 한 대당 하루 최대 8천여 번, 위치를 보내는 동안은 따로 묻지 않습니다). 시연·시험 규모에서는 문제가 없을 것으로 보지만, Vercel → **Usage** 에서 함수 호출 수를 한 번 봐 주세요. 한도에 가까우면 협업자에게 알려 주세요 (묻는 간격을 늘릴 수 있습니다).
- **부저 요청은 60초 뒤 만료**됩니다. 한참 뒤에 갑자기 울리지 않게 한 것입니다.
- **블루투스 보안은 아직 없습니다.** 목걸이 근처의 다른 휴대폰도 블루투스로 부저를 울릴 수 있습니다 (서버를 거치는 요청은 로그인한 가족만 가능). 실제로 쓰기 전에 목걸이 쪽에서 막아야 합니다.
- 현관 수신기는 이번에 뺐습니다. 텔레그램 봇 토큰을 따로 쓰고 계셨다면 더 이상 필요 없으니 BotFather에서 `/revoke` 하셔도 됩니다.
