# REMEMBER WAY AI — 구현 전 결정표 (2026-10-25 확정)

팀: 그럴게요 (동명중, 김동욱·양준원) · 결정자: 지도교사 · 학생 합의 완료

## 1. 범위·방향

| 항목 | 결정 | 비고 |
|---|---|---|
| 제품 구분 | 다차원 AI 시뮬레이터 | 변경 없음 |
| 한 문장 | 기기도 등록도 없이 사라진 치매 어르신을, 보호자의 기억만으로 찾게 돕고 그 경험으로 다음 실종을 막는다 | |
| AI 한 문장 | 보호자의 말을 경찰이 쓸 정보로 바꾸고, 빠진 것을 되묻고, 확인할 곳을 지도에 정리한다 | 코드 주석·발표·기획안 동일. "예측·추천·확률" 금지 |
| 구현 범위 | 화면 0~4 전부 + 환자 모드 | 예선 날 미구현은 README "상태"에 정직하게 |
| 만드는 순서 | **1→2→3 → 0 → 4 → 환자 모드** | 핵심(1~3)이 먼저 돌아가게 |
| GPS 하드웨어 | **제외** | 피지컬로 방향이 바뀌므로 |
| 평소 경로 축적 | **대화형 일지**로 (화면 0) | 첫 등록 한 번 자세히 → 매일 칩 탭 10초 → 새 장소·언급만 AI(호출 ⑤) → 주간 요약(호출 ⑥). 장소 4분류는 코드 규칙 |
| 사진 → 인상착의 (호출 ③) | 예선 제외, 본선용 | 이미지 모델 필요 |
| 환자 모드 | 어르신 폰 큰 버튼 → 서버 푸시로 보호자 알림 | 맨 마지막. 구독 저장용 KV 필요 → 거기까지 가면 붙임 |

## 2. 우선 확인 순서 (규칙 기반, 코드)

| 요소 | 점수 |
|---|---|
| 추억 장소 (첫 등록·"가고 싶다"고만 한 곳) | +3 |
| 최근 자주 가기 시작한 곳 (14일 방문 ≥ 이전 14일×2) | +3 |
| 자주 가는 곳 (30일 4회 이상) | +2 |
| 새로운 곳 (첫 등장, 2회 이하) | +2 |
| 기타 보호자 입력 장소 | +1 |
| 경로 위 교차로 | +2 |
| 반경(R_max) 밖 | −2 |

- 동점은 가까운 순. 보호자가 "이미 가 봤다"고 한 곳은 제외.
- 화면 3에 이 표를 그대로 보여 주고 **"임의 설정, 실험으로 조정"** 표기.
- R_max = 경과시간 × 보행속도(느림 0.5 / 보통 0.8 / 빠름 1.2 m/s).
- AI는 점수 계산에 관여하지 않는다. 장소를 보호자 말에서 꺼내는 것까지만.

## 3. 기술

| 항목 | 결정 |
|---|---|
| 프레임워크 | Next.js (App Router, TypeScript, Tailwind) |
| AI | Claude API (`@anthropic-ai/sdk`). 모델은 키 받은 뒤 호출 ①을 2~3개 모델로 돌려 보고 결정 → 기획안 5쪽에 기재 |
| 배포 | GitHub(코드, 공개) + Vercel(배포·환경변수) |
| 계정 | 학교·팀 공용 계정 새로 생성 (GitHub, Vercel, 카카오 개발자) |
| STT | 브라우저 Web Speech API. 안 되는 브라우저는 글쓰기 |
| 지도 | 카카오맵 JavaScript. 길찾기(도보 경로) API 권한 확인 필요 — 안 열리면 지도 표시 + 직선 거리로 시작 |
| 저장 | 보호자 기기 localStorage만. 서버 DB 없음 (환자 모드 푸시 구독만 예외) |
| 키 관리 | `.env.local`과 Vercel 환경변수에만. 저장소에는 `.env.example`만 |
| 시연 | 실시간 + 미리 저장한 결과 1건을 "녹화 결과"로 표시 |

## 4. 기본값 (반대 없어 확정)

- 환각 대조: 공백 제거 후 2글자 이상 연속 일치면 통과, 아니면 ⚠ (`lib/verify.ts`)
- 되묻기 최대 3개, 각 질문에 [모름] 버튼, 우선순위는 코드 고정 (`FOLLOWUP_PRIORITY`)
- 첫 화면 개인정보 문구 3줄: 이름 안 묻음 / 사진 저장 안 함 / 내 기기에만 저장
- 모바일 폭 기준, PC는 가운데 좁게
- 호칭 "어르신", 보호자에게 존댓말
- README: 한 문장·AI가 하는 일/안 하는 일·상태(미구현)·모의 데이터 안내

## 6. 구현 시작 패키지 (`rememberway-starter.zip`)

```
lib/schema.ts        스키마(단서·프로필·일지), 장소 4분류, 되묻기 우선순위, 가중치, 임계값
lib/diary.ts         일지 → 장소 분류(코드), 기록일 수
lib/prompts.ts       호출 ①②(당일 대화) + ⑤(일지 발화)·⑥(주간 요약) 프롬프트 초안
lib/verify.ts        스키마 검사, missing 재계산, 환각 대조(⚠)
lib/priority.ts      R_max, 우선 확인 순서 점수, "지금 할 일 3가지"(규칙)
lib/claude.ts        Claude API 래퍼 (서버 전용, 10초 타임아웃)
app/api/extract/     POST 호출 ① → 검증 → 플래그
app/api/followup/    POST 호출 ② → 코드 검증(허용 키·순서·3개)
app/api/diary/       POST 호출 ⑤ → 원문 대조·아는 장소 제외
data/mock_cases.json 모의 사례 3개 + 정답표(있는 항목/없는 항목) + 환각 함정 + 지표 정의
scripts/run_mock.ts  모의 사례 실행 → data/results_날짜.json (실험 기록)
docs/                확정안·화면구성·학생안 통합 문서
README.md, .env.example, .gitignore, package.json
```

학생이 할 일 순서:
1. 공용 GitHub 계정 → 저장소 생성 → 이 패키지 넣고 첫 커밋
2. `npx create-next-app` 으로 뼈대 만든 뒤 `lib/`, `app/api/`, `data/`, `scripts/` 덮어쓰기
3. 키 받으면 `.env.local` 작성 → `npm run mock` → 결과 보고 프롬프트 수정
4. 화면 1→2→3 프론트 제작 (`docs/화면구성` 참고)
5. Vercel 연결 → 환경변수 → 첫 배포

| 입력 방식 보강 (2026-10-29, 지도교사 실기기 피드백) | ① 음성: 안드로이드 크롬에서 문장이 반복 누적되던 문제 → 결과를 매번 처음부터 다시 조립하고 짧은 세션을 자동 재시작하는 방식으로 변경. ② 되묻기·✎ 수정·서식 모드 답변을 **눌러서 고르는 칩**(색×옷 종류, 이동수단+지나는 곳, 약·증상·이전 실종 선택지)으로. 자유 입력은 보충 칸으로만 | "평소 어느 길로 가세요?"에 글로 답하기 어렵고, 어르신·급한 보호자는 타이핑이 부담. 경로 그리기는 지도 정확도(OSM)와 시간상 보류 — 대신 "이동수단 + 지나는 곳"으로 받아 AI 요약·경찰 전달에 쓴다 |
| 입력·지도 2차 (2026-10-29 오전, 지도교사 결정) | ① **선택지 제거**: 모든 답은 말/글 자연어 → AI가 분석. 소지품 "있/없"만 코드가 해석. ② **도보 길찾기 연동**: OSRM 공개 서버(foot)로 집→후보 도보 경로·거리·갈림길. 갈림길을 "경로 위 교차로(+2)" 후보로 지도에 ✕ 표시. ③ **동선**: 반경 안 상위 후보 최대 5곳을 집에서 가까운 순으로 도는 경로(빨간 선)와 누적 거리·시간. ④ "카페·편의점·세탁소"처럼 종류만 말한 곳은 집 반경 안 실제 가게 2~3곳으로 펼쳐 후보에 넣음. ⑤ 지도는 OSM 표준(한국어 지명 일반 지도, 위성 아님) 유지 | 선택지도 부담이라는 실기기 피드백. "자주 가는 가게가 여러 개"인 실제 상황에 맞게 동선이 필요. OSRM·Nominatim은 공개 데모 서버라 1초 1회로 아끼고, 실패하면 직선거리로 내려감 — 시연 전 응답 확인 필요 |
| 설정 일원화·네이버 지도 준비 (2026-10-29) | 키·주소·동작 설정을 `.env.example`(설명서, 커밋) / `.env.local`(PC) / Vercel 환경변수(서비스) 세 곳 같은 이름으로. 네이버 지도는 `MAP_PROVIDER=naver` + `NAVER_CLIENT_ID`(공개) + `NAVER_CLIENT_SECRET`(서버 전용, 주소 Geocoding)로 켜짐. 바탕 지도·주소 좌표는 네이버, 가게 이름 검색·근처 가게·도보 길찾기는 OSM 공개 서버 유지 (네이버 Directions 5는 자동차 전용). 확인할 곳마다 네이버 지도 앱 도보 길안내 링크 | 지도교사: 카카오 제외, 네이버/구글 선호, 설정은 나중에 직접 수정하고 싶음. 네이버클라우드 Maps 신청: Dynamic Map·Geocoding(·Directions 5) |

### 추가 결정 (2026-10-29, 네이버 검색·동선)
- **가게 검색**: 네이버클라우드 NAVER API HUB "검색 > 지역"(`/search/v1/local`) 연동. 서버 함수 `/api/search`만 키를 가짐. 구 개발자센터 검색 API는 2026-07-31부터 신규 신청 불가라 쓰지 않음. 확인: "대전 중구 석교동 편의점" → GS25·CU 실제 좌표.
- **종류만 말한 곳**("편의점", "무인세탁소", "집 앞 카페"): 집 반경(최대 2km) 안의 실제 가게 최대 3곳으로 펼친다. 반경 밖 결과는 버리고 "집 근처, 지도에서 못 찾음"으로 둔다 (엉뚱한 먼 가게 금지). 이름으로 찾은 곳도 집에서 30km 넘으면 버린다.
- **돌아볼 동선 = 최단 순서**: 집에서 출발해 후보(최대 5곳)를 모두 들르는 순서 중 도보 거리 합이 가장 짧은 순서. OSRM `table`로 실제 도보 거리표를 받아 가능한 순서 전부(≤7곳은 전수, 그 이상은 최근접+2-opt)를 비교. 이전의 "가까운 곳부터" 규칙은 최적이 아니었음 (표본에서 1,974m → 1,511m).
- **지도 핀 번호 = 들르는 순서**. 우선 확인 순서(점수)는 아래 목록 번호이고 각 줄에 "지도 n" 배지로 연결. 동선에 없는 후보는 회색 점, 갈림길은 ✕.
- **정직 표기**: 공개 OSRM 서버는 도보 설정으로 불러도 자동차 도로망 기준일 수 있어 골목길이 빠질 수 있다. 화면에 "공개 길찾기 서버 결과, 참고용"이라고 적는다. 보행 전용 라우팅은 본선 과제.
- **위치 예측 아님**(불변): 동선·순서는 보호자가 말한 곳을 정리해 돌아보는 길이지 어르신이 있을 곳을 예측한 것이 아니다.
- **반응형**(2026-10-29 추가): 모바일 기준 그대로 두고, 760px 이상은 폭 720px·지도 420px, 1100px 이상은 폭 1120px에 요약 화면을 두 칸(왼쪽 글, 오른쪽 고정 지도 72vh)으로. PC로도 봄.
- **지도 이름표**: 줌 16 이상에서만 핀 옆에 짧은 이름(14자)을 붙이고, 화면 픽셀로 겹침을 검사해 겹치는 이름표는 숨긴다(번호 핀 → 점 → ✕ 우선, 오른쪽이 막히면 왼쪽). 핀을 누르면 전체 이름. "1. 겹치면 안 된다 2. 지도에서 보여야 한다"는 요구를 이렇게 맞춤.
- **갈림길(교차로) 표시 방식**(2026-10-29): 목록·점수 후보로는 넣지 않는다(보호자에게 "여길 가라고?"로 읽혀 어수선). 지도의 빨간 동선 위에 **이름표 없는 작은 ✕**로만 표시하고, 누르면 "갈림길 — 여기서 길을 잘못 들기 쉬워요". "지금 할 일"에 "가는 길의 갈림길(✕)도 살펴보세요" 한 줄. 근거(배회는 갈림길에서 시작)를 화면에 남기되 후보 목록을 어지럽히지 않는 절충. 가중치 표의 "경로 교차로 +2"는 표에 남기고 "목록 점수에는 넣지 않음"이라고 적는다.
- **동선은 우선순위를 지킨다**(2026-10-29, 지도교사): "예비 후보"를 따로 두지 않는다. 좌표를 찾은 후보 **전부**를 동선에 넣되, 점수가 높은 묶음부터 가고 같은 점수 안에서만 걷는 거리 최단 순서(전수 비교)로. 점수 낮은 곳(반경 밖 −2 등)도 빼지 않고 맨 뒤에 들른다. 이전의 "상위 5곳만 최단"은 우선순위와 어긋나 폐기.
- **동선 최적성 검증·수정**(2026-10-29): 실제 사례(후보 9곳)에서 근사 규칙(최근접+2-opt) 동선 6,892m vs 전수 비교 최단 6,588m → 304m(4.4%) 차이 확인. 14곳까지는 Held-Karp 동적계획법으로 정확한 최단을 구하도록 교체(무작위 3사례에서 전수 비교와 일치, 14곳 15ms). 15곳 이상은 근사이며 화면에 "근사"라고 표시.
- **길찾기 서버를 보행자용으로**(2026-10-29): 공개 OSRM은 자동차 도로망이라 일방통행 때문에 1→2 1,544m / 2→1 1,318m처럼 방향마다 달라 동선 순서가 왜곡됨(지도교사가 "2번 가려고 삥 돈다"로 발견). Valhalla 공개 서버(valhalla1.openstreetmap.de, costing=pedestrian)로 교체: 인도·골목·계단 포함, 일방통행 무시. 같은 구간 1,323m. OSRM은 Valhalla 장애 시 예비이며 그때는 화면에 "자동차 도로 기준, 참고용" 표시. 둘 다 키 없음·공개 서버라 시연 외 대량 호출은 하지 않는다.
- **집 동네를 말에서 추출**(2026-10-29): 부산 사례 테스트에서 "집은 부산 해운대구 좌동이에요"라고 말했는데 등록 정보의 대전 석교동이 지도 중심으로 쓰여 가게 검색이 전부 엉뚱했음. 호출 ① 스키마에 `home_dong`(시 구 동, 번지 금지, 없으면 null) 추가. 우선순위: 이번에 말한 집 동네 > 평소 등록 > 마지막 본 곳. 화면 2에서 ✎로 고칠 수 있고 요약문 "거주:"에도 반영.
