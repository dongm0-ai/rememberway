# 원격 부저 · 위치 단말 등록 (2026-11-20)

보호자가 웹 `/find` 에서 [소리 울리기]를 누르면, 멀리 있어도 어르신 휴대폰 앱을 거쳐 목걸이에서 소리가 나게 했다.
현관 수신기는 뺐다. 생성형 AI는 쓰지 않는다 (명령 전달과 측정값만 다룬다).

```
위치:  목걸이 →(블루투스)→ 어르신 휴대폰 앱 → /api/loc push → 보호자 웹 /track
부저:  보호자 웹 /find → /api/loc buzz.send → 어르신 휴대폰 앱(cmd.pending) →(블루투스)→ 목걸이 → cmd.result → 웹(buzz.status)
```

## 등록 방식

- 보호자 웹에서 어르신을 등록하면 **연결 코드 16글자**가 나온다 (기존과 같음).
- 어르신 휴대폰 앱에 코드를 넣고, 앱에서 주변 **목걸이를 찾아 하나 고른다**. 목걸이는 고정이 아니다 — 바꾸면 앱에서 다시 고른다.
- 앱이 고른 목걸이의 이름·펌웨어 id·연결 상태를 서버에 알린다 (`device.report`). 웹 설정과 `/find` 에 "등록된 위치 단말"로 보인다.
- 웹에서 단말을 따로 등록하지 않는다. 코드는 "보호자 계정 ↔ 어르신 휴대폰"을 잇고, 목걸이는 그 휴대폰에 딸려 온다.

## 서버 (`api/loc.js` — Vercel 함수 12개 한도 때문에 새 파일 없이 action 으로)

| 누가 | action | 하는 일 |
|---|---|---|
| 보호자 (로그인 + member) | `buzz.send {elderId, command}` | 부저 명령 저장. `BUZZER_FIND`(20초) · `BUZZER_ON`(10초) · `BUZZER_OFF`. 울리기는 3초에 한 번, 멈추기는 언제나 |
| 보호자 | `buzz.status {elderId, id}` | `pending` → `delivered`(휴대폰 도착) → `accepted` · `failed` · `expired` |
| 보호자 | `device.status {elderId}` | 앱이 마지막으로 알린 목걸이·연결 상태 |
| 앱 (연결 코드) | `push` 응답의 `commands` | 위치를 보낼 때 기다리던 명령을 같이 받는다 (따로 묻는 횟수를 줄임) |
| 앱 | `cmd.pending {key}` | 위치를 안 보내는 동안 10초마다 기다리는 명령을 묻는다 |
| 앱 | `cmd.result {key, id, status, response}` | 목걸이에 전달한 결과 |
| 앱 | `device.report {key, tracker, ble, gps, app}` | 연동한 목걸이와 상태 (바뀔 때와 5분마다) |

정한 것과 이유:

- **60초 만료.** 그 안에 휴대폰이 가져가 전달하지 못하면 버린다. 한참 뒤 갑자기 울리면 어르신이 놀라고, 보호자는 이미 다른 곳을 찾고 있다.
- **`accepted` 는 "목걸이가 요청을 받았다"까지.** 목걸이가 ACK 글자를 돌려줬을 때만 그렇게 표시한다. 실제로 소리가 났는지 확인할 방법은 없고, 화면에도 그렇게 적었다.
- **같은 명령을 두 번 울리지 않는 것은 앱이 맡는다** (명령 id 를 휴대폰에 기록). 서버는 결과가 올 때까지 같은 명령을 계속 준다 — 응답을 잃어도 명령이 사라지지 않게.
- **알림(FCM)을 쓰지 않는다.** 앱이 물어보는 방식이라 버튼을 누른 뒤 소리가 나기까지 최대 10초쯤 걸린다.
- 코드가 폐기되면(재발급·어르신 삭제) 앱의 모든 action 이 410 → 앱은 대기열을 비우고 멈춘다 (기존 `push` 와 같음).

## 서버에 새로 남는 것 (`docs/supabase.sql` 끝부분)

| 표 | 넣는 것 | 지우는 때 |
|---|---|---|
| `device_commands` | 연결 코드 해시, 명령 종류, 상태, 목걸이의 대답, 누른 가족의 계정 id, 시각 | 하루 뒤 / 어르신 삭제 |
| `device_status` | 연결 코드 해시, 목걸이 이름·펌웨어 id·버전, 블루투스·GPS 상태, 앱 버전, 시각 | 어르신 삭제 |

이름·주소·위치·블루투스 주소는 넣지 않는다.

> **지도교사 확인 필요.** `CLAUDE.md` 의 "서버 DB를 만들지 않는다"에 이 두 표가 예외로 추가돼야 한다 (예외 1 푸시 구독, 예외 2 위치 기록에 이어). 결정되면 결정표와 `CLAUDE.md` 에 날짜와 함께 적는다.

## 호스트가 할 일 (한 번)

1. Supabase → SQL Editor 에서 `docs/supabase.sql` 의 **"원격 부저·위치 단말 등록"** 구간을 Run 한다 (전체를 다시 Run 해도 안전).
2. 코드를 배포한다. SQL 을 아직 안 돌렸어도 위치 받기(`push`)는 그대로 된다 — 부저·단말 표시만 "서버에 문제가 있어요"로 나온다.
3. 어르신 휴대폰에 새 앱(Releases → `tracker-apk`)을 깔고, 연결 코드를 넣고 목걸이를 고른다.

## 화면

- `/find`: 서버를 거치는 [소리 울리기]·[소리 멈추기]가 기본. 진행 상태(보내는 중 → 휴대폰이 받음 → 목걸이가 받음 / 닿지 못함)를 보여 준다. 어르신이 휴대폰을 두고 나가신 경우를 위해 "근처에서 직접 연결"(이 휴대폰의 블루투스)은 접어서 남겼다.
- `/settings`: 연결 코드 아래에 "등록된 위치 단말".
- `/report`: 현관 수신기 알림(`?out=`)으로 들어오는 부분을 뺐다.
- `/track`: "움직이는 동안 10초마다 · 3분 멈추면 쉼" 설명을 지금 목걸이(가속도 센서 없음)에 맞게 고쳤다.

## 아직 안 된 것

- **목걸이 펌웨어 소스는 저장소에 없다.** 옛 펌웨어(`hardware/necklace/necklace.ino`)는 지금 앱·웹과 맞지 않아 지웠다. 목걸이가 지켜야 할 값은 `hardware/README.md` "블루투스 약속"에 있다.
- **블루투스 보안.** 목걸이의 부저 특성이 열려 있어 근처의 다른 휴대폰도 울릴 수 있다.
- 어르신이 휴대폰을 두고 나가시면 위치도 원격 부저도 되지 않는다.
- 앱이 강제로 종료되면 누군가 다시 [시작]을 눌러야 한다. 웹에는 "소식이 끊김"으로 보인다.
