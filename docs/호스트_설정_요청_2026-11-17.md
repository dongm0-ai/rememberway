# 호스트 설정 요청 — 보호자 계정 기능 켜기 (2026-11-17)

**누가 보나요:** Supabase와 Vercel 계정을 가진 호스트. 협업자는 두 서비스에 들어갈 수 없어서, 아래 순서대로 한 번씩만 해 주시면 됩니다.
**왜 필요한가요:** 이번에 "보호자 계정"(이메일 로그인), 가족 초대, 어르신별 공유 데이터가 들어갔습니다. 코드는 저장소에 있지만 **Supabase 표·로그인 설정·환경변수는 호스트가 눌러야** 켜집니다. 아래를 안 하면 로그인 화면이 "로그인 서버가 아직 설정되지 않았어요"라고 나옵니다.

- `<도메인>` = 서비스 주소. Vercel에서 쓰는 주소 그대로이고 `.env.example`의 `APP_URL`과 같습니다 (예: `https://rememberway.vercel.app`). 아래 `<도메인>`에 모두 같은 값을 넣어 주세요.
- 순서가 중요합니다 (①→⑦). 특히 ④(키 넣기) 다음에 ⑤(다시 배포)를 해야 키가 적용됩니다.
- **이미 쓰고 계신 환경변수는 그대로 둡니다.** AI 키(`UPSTAGE_API_KEY`·`GEMINI_API_KEY`), 네이버 키(`NAVER_*`), `MOCK_AI`, 푸시 알림 관련 값은 이번에 바꿀 것이 없습니다. 새로 필요한 것은 ④의 `SUPABASE_ANON_KEY` 하나뿐입니다.
- **이 코드가 GitHub `main`에 올라가면 Vercel이 자동으로 배포할 수 있습니다.** ①~⑤를 마치기 전에는 로그인 화면에 "로그인 서버가 아직 설정되지 않았어요"가 나오는 것이 정상입니다. 시연 일정이 가까우면 ①~⑤를 먼저 끝내 주세요.
- **키를 메신저·메일로 보내지 마세요.** 이 요청서에서 협업자에게 돌려줄 것은 각 단계의 "잘 됐어요 / 안 됐어요"와 증상 한 줄뿐입니다 (맨 아래 "돌려주실 것").

## ① Supabase에 새 표 만들기 (SQL)

**할 일**
1. Supabase 대시보드 → 이 서비스의 프로젝트 → 왼쪽 **SQL Editor** → **New query**.
2. 저장소의 `docs/supabase.sql` 파일을 열어, **`보호자 계정 (2026-11-17, 다시 Run 해도 안전)`** 이라고 적힌 주석 줄(파일 중간쯤)부터 **파일 끝까지** 복사해 붙여넣고 **Run**.
   - 파일 **전체**를 붙여넣어도, 몇 번 다시 Run 해도 안전합니다. 표 만들기는 `create ... if not exists`라서 이미 있는 표(`push_subs`, `app_kv`, `loc_events`)는 건드리지 않고, 끝쪽의 `alter ... set not null` 세 줄은 이미 적용돼 있으면 아무 일도 하지 않습니다 (이전 버전으로 만든 표를 고쳐 주는 줄입니다).
3. "Success"가 나오면 끝.

**잘 됐는지 보는 법** — 같은 SQL Editor에서 아래 세 개를 따로 Run 해 보세요.
```sql
-- (1) 새 표 5개가 보여야 합니다 (5행)
select table_name from information_schema.tables
where table_schema = 'public'
  and table_name in ('elders','elder_members','elder_data','invites','revoked_devices')
order by 1;

-- (2) 모두 rowsecurity = true 여야 합니다 (5행)
select tablename, rowsecurity from pg_tables
where schemaname = 'public'
  and tablename in ('elders','elder_members','elder_data','invites','revoked_devices')
order by 1;

-- (3) 세 줄 모두 is_nullable = NO 여야 합니다 (3행)
select table_name, column_name, is_nullable from information_schema.columns
where table_schema = 'public'
  and ((table_name = 'elder_members' and column_name = 'role')
    or (table_name = 'invites' and column_name in ('elder_id','expires_at')))
order by 1, 2;
```
(선택) 색인 확인: `select indexname from pg_indexes where indexname = 'elder_members_user';` → 1행.

**안 될 때:** 빨간 오류가 나오면 그 문장을 그대로 협업자에게 알려 주세요. 대개 "relation ... does not exist"인데, 이때는 파일 **전체**를 한 번에 Run 하면 해결됩니다. "column ... contains null values"가 나오면 이전 버전으로 만든 표에 빈 칸이 있는 행이 있다는 뜻이니, 그 문장을 협업자에게 알려 주세요 (시험 데이터라면 그 행을 지우고 다시 Run).

## ② 이메일 확인 끄기 ("Confirm email")

가입하자마자 바로 로그인되게 합니다. (Supabase 기본 메일은 시간당 몇 통만 보낼 수 있어서, 켜 두면 가입이 막힐 수 있습니다.)

**할 일**
1. Supabase → **Authentication** → **Providers**(또는 Sign In / Providers) → **Email**.
2. **Email 로그인이 켜져 있는지** 확인하고, **"Confirm email"을 끕니다** → **Save**.
   - 화면 이름이 조금 달라도 Email 제공자 설정 안의 "Confirm email" 스위치를 찾으시면 됩니다.

**잘 됐는지 보는 법:** ⑦의 가입 단계에서 **인증 메일을 기다리지 않고** 바로 화면이 넘어가면 됩니다.

**안 될 때:** 가입 뒤 "확인 메일을 보냈어요. 메일의 링크를 누른 뒤 [로그인]을 눌러 주세요."가 뜨면 스위치가 아직 켜져 있는 것입니다 (로그인 때는 "이메일 확인이 아직이에요"로 나옵니다).

## ③ 비밀번호 찾기 메일의 돌아올 주소 허용 (URL Configuration)

**할 일**
1. Supabase → **Authentication** → **URL Configuration**.
2. **Site URL**을 `https://<도메인>` 으로 (이미 같은 값이면 그대로 둡니다. `localhost` 주소로 남아 있으면 바꿔 주세요).
3. **Redirect URLs**에 **`https://<도메인>/login?reset=1`** 을 **Add URL**로 추가 → **Save**.
   - Vercel "미리보기(Preview)" 주소로도 시험하실 거면 그 주소의 `/login?reset=1`도 하나 더 추가합니다.

**잘 됐는지 보는 법:** 로그인 화면(`https://<도메인>/login`)에서 가입해 둔 이메일을 넣고 **[비밀번호 찾기]** → 메일이 오면 메일 속 링크를 누릅니다 → 우리 앱의 **"비밀번호 바꾸기"** 화면이 열리면 됩니다.
(메일은 Supabase 기본 발송이라 시간당 몇 통만 갑니다. 연속으로 여러 번 누르지 마세요.)

**안 될 때:** 링크가 첫 화면이나 `localhost`로 가면 Redirect URLs에 주소가 정확히 들어가지 않은 것입니다 (`https://<도메인>/**` 도 함께 추가해 보세요).

## ④ Vercel 환경변수: `SUPABASE_ANON_KEY` 넣기, `APP_URL`·`ALLOWED_HOSTS` 확인

로그인 화면이 Supabase 로그인 서버를 부르려면 **공개용(anon) 키**가 필요합니다. (service_role 키와 다른 키입니다.)

**할 일**
1. Supabase → **Project Settings**(톱니) → **API** → **anon / public** 키를 복사합니다. (`service_role` 키는 복사하지 않습니다.)
2. Vercel → 이 서비스 프로젝트 → **Settings** → **Environment Variables**.
3. **먼저 목록에서 `SUPABASE_ANON_KEY`가 이미 있는지 찾아 보세요.** Supabase를 Vercel의 Marketplace(통합)로 연결하셨다면 자동으로 만들어져 있을 수 있습니다.
   - **이미 있으면:** 새로 만들지 않습니다 (같은 이름을 또 만들면 "already exists" 오류). 그 항목 오른쪽 **⋯ → Edit**에서 **Production과 Preview에 체크**돼 있는지만 보고, 값이 이 프로젝트의 **anon / public** 키인지 확인합니다 (값이 가려져 있으면 그대로 두고 ⑤의 `/api/config` 점검에서 `anonKey`가 `null`이 아니면 맞는 것입니다). 값이 비어 있거나 `service_role` 키가 들어가 있으면 anon 키로 바꿉니다.
   - **`NEXT_PUBLIC_SUPABASE_ANON_KEY`만 있고 `SUPABASE_ANON_KEY`는 없으면:** 그대로 두셔도 됩니다. 앱이 `NEXT_PUBLIC_SUPABASE_ANON_KEY`(그리고 `NEXT_PUBLIC_SUPABASE_URL`)도 읽습니다. 새로 만들 필요 없습니다.
   - **없으면:** 이름 **`SUPABASE_ANON_KEY`**, 값에 붙여넣기, 적용 환경은 **Production과 Preview 모두 체크** → **Save**.
4. 같은 화면에 아래 두 개가 **이미 있는지**만 확인합니다 (Supabase를 Vercel에 연결할 때 자동으로 생긴 것입니다. 새로 만들 필요 없음):
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY` (비밀 — 어디에도 복사해 보내지 마세요)
5. **`APP_URL`과 `ALLOWED_HOSTS`에 실제 서비스 주소가 들어 있는지** 확인합니다. 서버는 우리 앱 주소에서 온 요청만 받습니다. 주소가 빠져 있으면 로그인 뒤의 어르신 목록·초대·위치 요청(`/api/loc`)이 **403(FORBIDDEN)** 으로 막히고, AI 호출도 막힙니다.
   - `APP_URL` = `https://<도메인>` (주소 앞의 `https://`까지).
   - `ALLOWED_HOSTS` = 주소만 쉼표로 (예: `rememberway.vercel.app,localhost:3000`). `https://`는 붙이지 않습니다. 직접 도메인(예: `example.com`)을 쓰시면 그 주소도 넣습니다. 둘 중 하나에만 있어도 되지만, 둘 다 맞춰 두시는 것이 안전합니다. (기본값이 `rememberway.vercel.app`이라 그 주소를 그대로 쓰시면 비워 두셔도 됩니다. Vercel이 주는 `…-dongm0-ai.vercel.app` 미리보기 주소는 자동으로 허용됩니다.)
   - 어르신 폰 앱이 위치를 보내는 `push`만 이 검사 없이 받습니다.

**잘 됐는지 보는 법:** Environment Variables 목록에 이름 3개(`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_ANON_KEY` — URL·anon 키는 `NEXT_PUBLIC_` 이름이어도 됩니다)가 보이고, `SUPABASE_ANON_KEY`의 환경에 Production·Preview가 적혀 있으며, `APP_URL`/`ALLOWED_HOSTS`에 실제 주소가 들어 있으면 됩니다. (실제 적용 여부는 ⑤에서 확인)

**안 될 때:** 이름을 잘못 적으면(예: `SUPABASE_ANON`, 공백 포함) 로그인 화면이 "로그인 서버가 아직 설정되지 않았어요 (관리자 설정 필요)"라고 나옵니다. 이름을 정확히 다시 확인하세요. 로그인은 되는데 어르신 등록·목록이 계속 실패하면 `APP_URL`/`ALLOWED_HOSTS`(위 5번)를 의심하세요.

## ⑤ 다시 배포 (Redeploy)

환경변수는 **새로 배포한 뒤부터** 적용됩니다.

**할 일**
1. Vercel → 프로젝트 → **Deployments**.
2. 가장 위의 **Production** 배포 오른쪽 **⋯** → **Redeploy** → 확인. (이 배포의 커밋이 GitHub `main`의 최신 커밋인지도 한 번 봐 주세요.)
3. 상태가 **Ready**가 될 때까지 기다립니다.

**잘 됐는지 보는 법** (브라우저 주소창에 아래 주소를 열어 봅니다)
- `https://<도메인>/api/config` → 글자 중간에 `"supabase":{"url":"https://…supabase.co","anonKey":"…"}` 처럼 **`url`과 `anonKey`가 둘 다 `null`이 아니면** 성공입니다. (`anonKey` 값은 화면 캡처에 담지 마세요.)
- `https://<도메인>/sw.js` → 맨 위쪽에 **`rw-v65`** 가 보이면 새 화면 파일이 배포된 것입니다.

**안 될 때:** `anonKey`가 `null`이면 ④의 Production 체크가 빠졌거나 Redeploy를 안 한 것입니다 (`NEXT_PUBLIC_SUPABASE_ANON_KEY` 이름도 읽으니 둘 중 하나만 있으면 됩니다). `url`이 `null`이면 `SUPABASE_URL`도 `NEXT_PUBLIC_SUPABASE_URL`도 없는 것입니다.

## ⑥ 어르신 폰 앱 설치 (GitHub 릴리스 `tracker-apk`)

어르신 폰용 위치 중계 앱은 **아직 어르신 폰에 배포한 적이 없습니다.** 어르신 폰에 앱을 설치할 때 **GitHub 릴리스 `tracker-apk`의 최신 APK**를 사용해 주세요. (`android/` 폴더 변경이 GitHub에 올라가면 Actions가 APK를 새로 만들어 같은 릴리스를 바꿉니다. **릴리스 설명의 "커밋 xxxxxxx"가 `android/` 폴더를 마지막으로 바꾼 커밋과 같아야** "가족이 연결을 끊으면 멈추고 알려 주는" 최신 동작이 들어 있습니다.)

**할 일**
1. 먼저 GitHub 저장소 → **Actions** → **android-apk**의 가장 최근 실행이 초록색(성공)인지 봅니다.
2. 어르신 폰(또는 시연용 폰)에서 GitHub 저장소 → **Releases** → **tracker-apk** → **`RememberWay-location.apk`** 를 받아 설치합니다.
   - 시제품(디버그 빌드)이라 "출처를 알 수 없는 앱 설치"를 허용해야 설치됩니다.
3. 앱을 열고, 보호자 앱 **⚙ 설정 → 어르신 폰 연결 코드**에 보이는 16글자 코드(하이픈 `-`은 넣어도 안 넣어도 됩니다)를 넣고 **[시작]**. 블루투스·알림 권한을 허용합니다.
   - 연결 코드는 ⑦에서 어르신을 등록해야 생깁니다. 그래서 이 단계의 마지막 입력은 ⑦ 뒤에 하셔도 됩니다.
   - **연결 코드는 어르신을 처음 등록한 그 폰(브라우저)의 ⚙ 설정에서만 보입니다.** 코드는 그 브라우저에만 저장되기 때문입니다. 그래서 **이 단계는 시크릿(사생활 보호) 창에서 하지 마세요** — 창을 닫으면 코드가 사라집니다. 설정 화면에서 위치 수집 동의 문구에 체크를 해야 코드가 보입니다.
   - 코드가 안 보이면(다른 기기·창에서 등록했거나 사이트 데이터를 지운 경우), 처음 등록한 가족(관리자, owner)이 **⚙ 설정 → 어르신 폰 연결 코드 → [다시 만들기]** 로 새 코드를 만들 수 있습니다. 이때 옛 코드는 바로 끊기니, 어르신 폰 앱에 새 코드를 넣어야 합니다.

**잘 됐는지 보는 법:** GitHub 저장소에서 `android` 폴더를 열면 맨 위에 마지막 커밋 줄이 보입니다. 그 커밋의 앞 7글자가 릴리스 설명의 "커밋 xxxxxxx"와 같으면 됩니다 (이 문서를 쓴 시점의 마지막 `android/` 커밋은 `e8dfc40`). 다르면 릴리스 커밋 이후에 `android/` 폴더가 바뀐 커밋이 없는지 보고 (저장소 → Commits에서 `android` 경로로 걸러 보기), 있으면 Actions 실행이 끝난 뒤 다시 받습니다. 앱을 열었을 때 상태 글이 보입니다. 보호자 앱 **📍 실시간 위치** 탭에 위치 점과 "몇 분 전"이 나오면 연결된 것입니다. (목걸이가 없거나 멀리 있으면 점이 안 나올 수 있습니다.)

**안 될 때:** 앱에 "가족이 연결을 끊었어요. 보호자에게 새 연결 코드를 받아 넣어 주세요."가 뜨면 그 코드는 폐기된 것입니다 — 보호자 앱 ⚙ 설정에서 새 코드를 확인해 다시 넣습니다.

## ⑦ 전체 확인: 가입 → 초대 → 두 번째 계정에서 같은 어르신 보기

기기 두 개(또는 한 기기의 일반 창 + 시크릿 창)와 이메일 두 개를 준비합니다. **보호자1은 일반 창**에서 하고, 시크릿 창은 보호자2 용으로만 쓰세요 (어르신 폰 연결 코드는 어르신을 등록한 창에서만 보이고, 시크릿 창은 닫으면 사라집니다). **시험용 호칭·장소만 쓰세요. 실제 어르신의 이름·주소는 넣지 않습니다.**

1. **보호자1:** `https://<도메인>/login` 을 엽니다. 맨 위에 **"치매 어르신은 즉시 신고 대상입니다. 먼저 112에 전화하세요."** 와 빨간 **📞 112** 버튼이 보이는지 봅니다.
2. 이메일·비밀번호(6자 이상)를 넣고 **[가입]**. 메일을 기다리지 않고 바로 넘어가야 합니다 (②가 잘 된 것).
3. 어르신 등록 화면이 나오면 **호칭**(예: "어머니")을 적습니다 (이 폰에 옛 등록 정보가 있으면 "이 폰의 등록 정보를 새 어르신으로 올릴까요?"가 먼저 나옵니다). 아래쪽에 **📍 실시간 위치 · 🚨 실종자 찾기 · 📝 추억의 장소** 탭 3개가 보입니다.
4. **📝 추억의 장소**에서 시험용 장소를 하나 저장합니다.
5. 오른쪽 위 **⚙ 설정 → 가족 초대 → [초대 QR 만들기]** → QR과 링크가 나옵니다 (24시간 안에 한 번만 쓸 수 있음).
6. **보호자2(다른 기기/시크릿 창):** QR을 카메라로 찍거나 링크를 열면 `/join` 화면 → 로그인 화면으로 갑니다 → 두 번째 이메일로 **[가입]**(또는 로그인).
7. "○○ 정보를 함께 보게 됐어요"가 나오고 **같은 호칭의 어르신**이 보이면 성공입니다. **📝 추억의 장소**에서 4번의 장소가 보이고, 보호자1의 **⚙ 설정 → 가족 목록**에 **가족 1 (나) · 관리자**와 **가족 2**가 보여야 합니다. (가족끼리도 이메일은 보여 주지 않고 들어온 순서로만 표시합니다.)
8. 같은 QR·링크를 한 번 더 열어 보세요 → "이미 사용된 초대예요" 라고 나오면 정상입니다 (1회용).

**안 될 때(증상 한 줄씩)**
- "로그인 서버가 아직 설정되지 않았어요" → ④·⑤ 확인. 
- 가입이 "이미 가입된 이메일"/로그인 실패 → 같은 이메일로 이미 가입했는지 확인 (Supabase → Authentication → Users에 보입니다).
- 어르신 등록·초대에서 "서버 저장소가 아직 연결되지 않았어요" 또는 "서버에 문제가 있어요" → ①(표 생성)이 안 됐거나 ④·⑤(키·재배포)가 안 된 것입니다. `elders` 표가 있는지 먼저 보세요.
- 초대 링크가 "초대 기한(24시간)이 지났어요" → 새 QR을 만들어 주세요.

# 본선(11/22) 시연 점검표

시연 **전날**과 **당일 시연 직전**에 한 번씩 위에서부터 확인합니다. 체크는 사람이 합니다.

**계정·데이터 (전날까지)**
- [ ] 시연 계정 **2개**(보호자1·보호자2)를 만들어 두었다. 이메일·비밀번호는 시연팀만 아는 곳에 적어 둔다 (이 문서나 저장소에 적지 않는다).
- [ ] 보호자1이 **시험용 어르신 한 분**(호칭만)을 등록했고, 추억의 장소 몇 곳을 저장했다. **실제 어르신의 이름·집 주소는 넣지 않았다.**
- [ ] **초대 완료:** 보호자2 계정이 같은 어르신에 들어와 있고, ⚙ 설정 → 가족 목록에 가족 1·가족 2가 보인다.
- [ ] 시연 중에 **초대 QR을 직접 보여 줄 거라면**, 시연 직전에 새 QR을 만든다 (24시간·1회 — 전날 만든 것은 이미 쓰였거나 기한이 지났을 수 있다). 시연용으로 쓸 **세 번째 이메일**을 준비해 두면 좋다.
- [ ] 시연 기기마다 **계정을 하나로 고정**했다. (한 폰에서 다른 계정으로 로그인하면 이 폰에 있던 이전 계정 사본이 지워진다. 서버 데이터는 그대로지만 리허설이 꼬일 수 있다.)

**기기·화면**
- [ ] 시연 PC·폰에서 **자동 로그인**이 되어 앱을 열면 바로 탭 3개가 보인다. 시연 전에 **어르신 탭을 한 번 열어 사본을 받아 둔다** (서버 장애 때 이 사본으로 찾기 흐름이 돈다).
- [ ] 로그아웃 상태로 `/login`을 열어 **112 고정 문구와 빨간 112 버튼**이 맨 위에 보이는지 확인했다.
- [ ] 앱을 완전히 닫았다가 다시 열어 새 화면이 뜬다 (서비스워커가 `rw-v65`로 바뀌었는지 — 옛 화면이면 한 번 더 새로고침).
- [ ] Vercel 환경변수 **`APP_URL`/`ALLOWED_HOSTS`**에 시연 주소가 들어 있다 (빠지면 로그인 뒤 `/api/loc`가 403).
- [ ] Vercel 환경변수 **`MOCK_AI=0`** (시연 때는 반드시 0). 화면에 "모의 응답" 배너가 안 보인다. AI 호출이 한 번이라도 되는지 `실종자 찾기`에서 확인했다.
- [ ] 인터넷이 약한 곳을 대비해 **서식 모드(AI 없이)** 로도 한 번 진행해 보았다.

**어르신 폰 연결**
- [ ] 보호자1 폰의 **⚙ 설정 → 어르신 폰 연결 코드**를 시연용 어르신 폰 앱에 넣었다 (코드는 어르신을 등록한 폰·브라우저의 설정에서만 보이니 시크릿 창으로 등록하지 않았다). 이후 **재발급하지 않는다** (재발급하면 어르신 폰의 옛 코드가 바로 끊긴다).
- [ ] 보호자 앱 **📍 실시간 위치**에 위치 점과 "몇 분 전"이 나온다. 목걸이·GPS가 시연 환경에서 안 되면, 미리 화면을 찍어(화면 녹화) 둔 영상을 쓰고 발표 때 "미리 찍어 둔 영상입니다"라고 말로 밝힌다 (모의 응답·미리 찍어 둔 영상은 숨기지 않는다).
- [ ] 폰 배터리·블루투스·위치 권한·절전 예외(앱이 백그라운드에서 꺼지지 않게)를 확인했다.

**끝난 뒤**
- [ ] 시험용 어르신 데이터는 보호자1(owner)이 ⚙ 설정 → **어르신 데이터 모두 지우기**로 지운다. 위치 기록(`loc_events`)은 30일 뒤 자동으로 지워진다 (먼저 지우려면 위치 화면의 [찾은 뒤: 위치 기록 모두 지우기]).
